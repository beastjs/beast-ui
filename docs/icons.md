# Icons

Every app draws icons the same way. Each icon is an `.svg` file, a script turns
the folder of files into one TypeScript module, and a small `Icon` component
draws an icon by name. This guide explains the pieces, sets them up in a new
app, and moves an existing app's `icons.ts` over.

| Command | What it does |
| --- | --- |
| `bun run icons:build` | Builds `icons.ts` from the `.svg` files. |
| `bun run icons:check` | Fails when `icons.ts` is out of date. For CI or a pre-commit hook. |
| `bun ~/Code/beast-ui/scripts/migrate-icons.ts` | Moves an older `icons.ts` map to `.svg` files. Once per app. |

## How the pieces fit

```
svg/search.svg ──┐
svg/menu.svg   ──┼── bun run icons:build ──▶ icons.ts ──▶ Icon ──▶ Icon(name="search")
svg/color/*.svg ─┘   (scripts/build-icons.ts)
```

| File | What it holds | Who edits it |
| --- | --- | --- |
| `svg/<name>.svg` | One icon, as exported from its icon set or your editor. | You |
| `svg/color/<name>.svg` | An icon that keeps its own colors, such as a brand logo. | You |
| `icons.ts` | Every icon's markup keyed by name, and the `IconName` type. | The build. Never by hand. |
| `Icon.btsx` or `index.tsx` | The component. | Copied once from this repo |
| `scripts/build-icons.ts` | The build. | Copied once from this repo |

The file name is the icon's name: `svg/search.svg` is `name="search"`.
`IconName` is the list of those names, so TypeScript rejects a misspelled name
and suggests the closest one.

## What build-icons.ts does

The build runs each file through [SVGO](https://svgo.dev). For each file it:

1. **Checks the name.** Lowercase letters, digits and dashes. Dots and
   underscores are accepted too, so names apps already use, such as
   `re-up.ph`, keep working.
2. **Redraws the icon on a 24×24 grid.** A 16px or 20px icon is scaled up. A
   wide or tall icon is centered in the square, the way a browser draws it in a
   square `<svg>`. Afterwards a `stroke-width` means the same thing in every
   icon.
3. **Keeps the paint set on the root `<svg>`.** `Icon` renders its own root, so
   `fill`, `stroke` and similar attributes from the file's root move into the
   icon. Icon sets such as Lucide put them there.
4. **Turns every color into `currentColor`**, so the icon follows the text
   color. Files in `svg/color/` skip this step and keep their colors.
5. **Removes what does nothing:** comments, editor metadata, `font-size` on
   shapes, `transform-origin="0 0"`, default values, and extra digits in paths.
6. **Prefixes ids with the icon name.** An id `g` in `search.svg` becomes
   `search-g`, and so do the gradients and animation timings that refer to it,
   so two icons on one page never share an id.
7. **Leaves the shapes of an animated icon alone.** An animation can target a
   transform, a radius or a path. Animated icons only get the clean-ups in
   step 5, and the grid transform from step 2 stays on a wrapping `<g>`.

Then it writes `icons.ts`, sorted by name. For example, this 16px file:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 16 16" fill="none" stroke="black" stroke-width="1.5" stroke-linecap="round">
  <path d="M2 4h12M2 8h12M2 12h12" font-size="18"/>
</svg>
```

becomes this entry, on the 24px grid, in the text color:

```ts
// Generated by build-icons.ts from ../svg. Do not edit it by hand:
// add or change an .svg file there, then run `bun run icons:build`.

export const ICON_VIEWBOX = '0 0 24 24'

export const icons = {
  menu: '<path fill="none" stroke="currentColor" stroke-linecap="round" stroke-width="2.25" d="M3 6h18M3 12h18M3 18h18"/>',
}

export type IconName = keyof typeof icons
```

When a file cannot be drawn, the build stops and names the file and the
problem. See [Messages](#messages).

## Where the icons live

### Inside beast-ui: the `@beast-ui/icons` package

The web and docs apps share one set of icons, so the icons live in their own
workspace package rather than in either app:

```
packages/icons/
  package.json     name "@beast-ui/icons"; exports "." → ./src/index.ts
  svg/             the .svg files
  src/icons.ts     built
  src/Icon.btsx    the component
  src/types.ts     IconProps
  src/index.ts     exports Icon, icons, IconName and IconProps
  env.d.ts         lets the package typecheck its .btsx import on its own
```

How `import { Icon } from '@beast-ui/icons'` finds the component:

1. The root `package.json` lists `"workspaces": ["apps/*", "packages/*"]`, so
   Bun treats `packages/icons` as a package named `@beast-ui/icons`.
2. Each app lists `"@beast-ui/icons": "workspace:*"` in its dependencies.
   `bun install` links `apps/<app>/node_modules/@beast-ui/icons` to
   `packages/icons`. Nothing is published or copied.
3. The package's `exports` field points the bare name at `src/index.ts`.
4. The package ships source, not built JavaScript. Each app's bundler (Vite in
   docs, Rsbuild in web) compiles `Icon.btsx` with the same Beast plugin it
   uses for the app's own files.
5. Each app's `tsconfig.json` includes `../../packages/icons/src`, as it
   includes `../../packages/registry/ui`.

`Icon` uses no Tailwind classes, so the apps need no `@source` line for it.

To give a new app in `apps/` the icons:

1. Add `"@beast-ui/icons": "workspace:*"` to its `dependencies`.
2. Add `"../../packages/icons/src"` to `include` in its `tsconfig.json`.
3. Run `bun install`, then restart the app's dev server. A running dev server
   can hold on to stale modules after a new workspace link.
4. Import it: `import { Icon, type IconName } from '@beast-ui/icons'`.

`@beast-ui/icons` exists only inside this repo. It is private and not
published, so other repos cannot install it.

### In any other app: a folder in the app

Each of your other apps has its own icons, so each keeps them in its own folder
and keeps importing from `@/lib/icons`, as it does today:

```
src/lib/icons/          lib/icons/ in Next.js apps without src/
  svg/                  the .svg files
  svg/color/            icons that keep their colors
  icons.ts              built
  Icon.btsx             Beast apps: the component
  types.ts              Beast apps: IconProps
  index.ts              Beast apps: what @/lib/icons exports
  index.tsx             React apps: the component and its exports
scripts/build-icons.ts  the build, copied from beast-ui
```

Call sites keep the same import path, so moving an app over changes the folder,
not every file that draws an icon.

## Set up a new app

Run these from the app's folder. The paths use `src/lib/icons`. Use
`lib/icons` if that is where the app keeps `lib`.

1. Add SVGO and the build:

   ```bash
   bun add -d svgo
   ```

   ```bash
   mkdir -p scripts src/lib/icons/svg && cp ~/Code/beast-ui/scripts/build-icons.ts scripts/
   ```

2. Add two scripts to `package.json`:

   ```json
   "icons:build": "bun scripts/build-icons.ts --svg src/lib/icons/svg --out src/lib/icons/icons.ts",
   "icons:check": "bun scripts/build-icons.ts --svg src/lib/icons/svg --out src/lib/icons/icons.ts --check"
   ```

3. Add the component.
   - Beast apps: copy it from this repo.

     ```bash
     cp ~/Code/beast-ui/packages/icons/src/{Icon.btsx,types.ts,index.ts} src/lib/icons/
     ```

   - React and Next.js apps: save [the React component](#the-react-component)
     as `src/lib/icons/index.tsx`.
4. Save a first icon, such as `src/lib/icons/svg/search.svg`, then build:

   ```bash
   bun run icons:build
   ```

5. Draw it. In Beast, `import { Icon } from '@/lib/icons'` and then
   `Icon(name="search" className="size-4")`. In React,
   `<Icon name="search" className="size-4" />`.
6. Run `bun run icons:check` wherever the app's checks run, such as CI or a
   pre-commit hook, so a changed `.svg` without a rebuilt `icons.ts` fails.

This needs the `@/*` path alias in `tsconfig.json`, and in Beast apps a
`declare module '*.btsx'` in `env.d.ts`. All your apps already have both.

### The React component

```tsx
import type { SVGProps } from 'react'
import { ICON_VIEWBOX, icons, type IconName } from './icons'

export type { IconName }

export interface IconProps extends Omit<SVGProps<SVGSVGElement>, 'name' | 'color' | 'dangerouslySetInnerHTML'> {
  name: IconName
  /** Width and height in pixels. A size class such as `size-5` overrides it. */
  size?: number
  /** Any CSS color. Without it the icon takes the surrounding text color. */
  color?: string
  /** Names an icon that means something on its own. Without it the icon is hidden from screen readers. */
  label?: string
}

export function Icon({ name, size = 16, color, label, style, ...props }: IconProps) {
  return (
    <svg
      xmlns='http://www.w3.org/2000/svg'
      viewBox={ICON_VIEWBOX}
      width={size}
      height={size}
      fill='currentColor'
      strokeLinecap='round'
      strokeLinejoin='round'
      role={label ? 'img' : undefined}
      aria-label={label}
      aria-hidden={label ? undefined : true}
      suppressHydrationWarning
      {...props}
      style={{ flexShrink: 0, color, ...style }}
      dangerouslySetInnerHTML={{ __html: icons[name] }}
    />
  )
}
```

It differs from the Beast one in three ways:

- `size` defaults to `16`, as in your React apps. The Beast one defaults to
  `20`. Keep whichever the app used before.
- It passes any other `<svg>` prop through, such as `onClick`, `style` or
  `strokeWidth`, as your React component did.
- It has no `'use client'`. It has no state or effects, so Next.js can render
  it on the server. See [Size and speed](#size-and-speed).

It keeps `suppressHydrationWarning` from your current component. Both
components set round line caps and joins on the root, as the old ones did, so
icons that relied on them look the same.

## Move an existing app over

About 40 of your apps have an `icons.ts` map of `{ symbol, viewBox, set }`,
often with a `logos.ts` or `dev.ts` beside it. A dry run on 2026-09-25 moved
3,533 icons from 40 apps. Six of them (rf, protap, high-profile, launch-day,
deals and beast.docs, 1,081 icons) were compared pixel by pixel, and every icon
came out the same.

Work on a branch with a clean working tree, from the app's folder.

1. **Add SVGO, the build and the scripts:** steps 1 and 2 of
   [Set up a new app](#set-up-a-new-app).
2. **Write the `.svg` files from the old maps.** List every map file. Leave
   out `unused.ts`.

   ```bash
   bun ~/Code/beast-ui/scripts/migrate-icons.ts --svg src/lib/icons/svg src/lib/icons/icons.ts src/lib/icons/logos.ts
   ```

   It prints what it wrote, what it skipped and why, and where the comparison
   page is:

   ```
   Wrote 242 icons: 226 to src/lib/icons/svg, 16 to src/lib/icons/svg/color (they keep their colors).

   Skipped 1:
     images: has no symbol string in icons in icons.ts. Its keys: symbold, viewBox, set.

   Compare before and after: open /var/folders/…/icons-preview.html
   ```

   - An icon goes to `color/` when its markup has a color other than
     `currentColor`, or a gradient. An icon that should follow the text color,
     such as one with a hard-coded black, belongs in `svg/`: move the file.
   - `set` becomes a comment in the file, such as `<!-- mingcute -->`.
   - Icons squeezed into 16px with `scale(0.667)` get their 24px art back.
   - It never overwrites a file. After fixing a skipped icon, run it again and
     it writes only that one.
3. **Open the comparison page.** Each card shows the icon as the old component
   drew it and as the new `Icon` draws it, with the share of pixels that
   differ. A card over 1% turns red and comes first. Expect none.
4. **Fix what was skipped**, then run step 2 again. The dry run found these:

   | App | Icon | Problem | Fix |
   | --- | --- | --- | --- |
   | and-cash, bt, end-game, hyfe, rf | `user` | Its `<g>` is never closed. | Add `</g>` at the end. |
   | hyfe, rf, deals | `sidebar` | A stray `scale-80` attribute on the `<path>`. | Delete `scale-80`. |
   | hyfe, rf | `plugplay`, `strength_` | One `</g>` too many at the end. | Delete the last `</g>`. |
   | foreplay | `coinsph` | Ends with a stray `</svg>`. | Delete it. |
   | end-game | `+` | Not a usable name. | Rename it, such as `plus`, and its call sites. |
   | protap | `images` | Typo: `symbold` instead of `symbol`. The icon draws nothing today. | Rename the key to `symbol`. |

5. **Build.** This overwrites the old `icons.ts`, so do it after step 2, which
   reads it:

   ```bash
   bun run icons:build
   ```

6. **Replace the component and delete the old files.**
   - Beast apps: delete the old component first. Several apps name it
     `icon.btsx`, and on macOS copying `Icon.btsx` over it would keep the old
     lowercase name, which breaks on case-sensitive systems such as Linux CI.

     ```bash
     rm -f src/lib/icons/icon.btsx src/lib/icons/Icon.btsx
     ```

     ```bash
     cp ~/Code/beast-ui/packages/icons/src/{Icon.btsx,types.ts,index.ts} src/lib/icons/
     ```

   - React apps: replace `index.tsx` with [the React component](#the-react-component),
     and delete `types.ts`.
   - Both: delete `logos.ts`, `dev.ts` and `unused.ts`. Their icons are in
     `svg/` now.
7. **Update the call sites.** This lists what to change:

   ```bash
   grep -rnE "lib/icons/(types|icons|logos|dev)|IconNameType|LogoNameType|DevIconNameType|svgStyle|<Icon[^>]* solid|Icon\([^)]* solid|<Icon[^>]*onClick|Icon\([^)]*onClick" src --include='*.ts' --include='*.tsx' --include='*.btsx'
   ```

   | Find | Change it to | Why |
   | --- | --- | --- |
   | Imports from `@/lib/icons/types`, `/icons`, `/logos` or `/dev` | `@/lib/icons` | It is one module now. |
   | `IconNameType`, `LogoNameType`, `DevIconNameType` | `IconName` | Logos are icons now. |
   | `solid` on an icon | Delete it. | It was the default. No app passes `solid={false}`. |
   | `onClick` on an icon | Put the icon in a `button` with the `onClick` and an `aria-label`. | A clickable `<svg>` cannot be reached by keyboard. The Beast `Icon` no longer takes `onClick`. |
   | `svgStyle` | Add its classes to `className`. | The icon is one element now. |

8. **Check the spacing.** The old components wrapped the `<svg>` in a `div`.
   The Beast one also gave it a 3px margin (`m-0.75`) and applied `className`
   to both elements. Open the pages that show icons:
   - Where an icon now sits closer to its neighbors, add `m-0.75` to its
     `className` to get the old spacing back.
   - Classes that add up no longer apply twice. An icon with `opacity-90` is
     now 90% opaque, not 81%.
9. **Delete icons nothing uses.** See [Size and speed](#size-and-speed).
10. **Typecheck, run the app, and commit** `svg/`, `icons.ts`, the component,
    `scripts/build-icons.ts`, `package.json` and `bun.lock`.

## Day to day

**Add an icon.** Save it as `svg/<name>.svg`, run `bun run icons:build`, and
commit both files. Any icon set works as exported, whatever its grid. Name new
icons with lowercase words joined by dashes.

**Change or remove an icon.** Replace or delete the file, then build. After a
removal, `IconName` no longer has the name, so TypeScript points at its call
sites. `.btsx` files are not typechecked, so in Beast apps search for the name
too.

**An icon that keeps its colors.** Put it in `svg/color/`. The build does
everything else the same. The `color` prop and the text color only change the
parts drawn in `currentColor`.

**An outline version of a filled icon.** Add a second file, such as
`heart-outline.svg`, with `fill="none" stroke="currentColor" stroke-width="1.5"`
on its root `<svg>`. The build moves them into the icon. This only works when
the icon's shapes set no `fill` of their own.

## Size and speed

`icons.ts` is one module. Every bundle that imports `Icon` carries all of it,
whichever icons its pages draw. An icon costs about 0.8 KB, or 0.3 KB
compressed.

Most of your apps' icon modules are under 50 KB. The largest, from the dry run:

| App | Before (compressed) | After (compressed) | Unused |
| --- | --- | --- | --- |
| rf | 368 KB (128 KB) | 239 KB (82 KB) | 19 of 291 |
| hyfe | 368 KB (128 KB) | 239 KB (82 KB) | 19 of 290 |
| repl | 229 KB (73 KB) | 205 KB (69 KB) | 43 of 239 |
| protap | 296 KB (104 KB) | 203 KB (62 KB) | 11 of 242 |
| drop-zone | 171 KB (56 KB) | 156 KB (53 KB) | 65 of 149 |
| foreplay | 169 KB (53 KB) | 142 KB (46 KB) | 45 of 175 |
| high-profile | 142 KB (47 KB) | 112 KB (40 KB) | 69 of 178 |
| launch-day | 135 KB (45 KB) | 110 KB (39 KB) | 21 of 169 |

Three things keep it small:

1. **Delete icons nothing uses.** `--unused` lists icons whose name never
   appears in quotes in the app's source:

   ```bash
   bun scripts/build-icons.ts --svg src/lib/icons/svg --out src/lib/icons/icons.ts --check --unused src
   ```

   A name built at runtime, such as `` `${kind}-outline` ``, is not found, so
   check each one before deleting its file. Then run `bun run icons:build`.
2. **In Next.js, keep `Icon` a server component.** Without `'use client'`, a
   page that draws icons only from server components sends no icon data to the
   browser. A client component that draws an icon still pulls `icons.ts` into
   the client bundle. 27 of your 30 React apps have `'use client'` at the top
   of their icon component today.
3. **If a client bundle is still too large after that, switch to an SVG
   sprite.** The build would write one `icons.svg` that the browser downloads
   and caches once, and `Icon` would draw `<use href="/icons.svg#search"/>`.
   This is not built yet.

## Keeping the script the same everywhere

Each app has its own copy of `scripts/build-icons.ts`. The copy in
`beast-ui/scripts/` is the original, and the others should match it exactly.
Its tests are in `beast-ui/tests/icons.test.ts`, so change the script in
beast-ui first.

To list the apps whose copy differs:

```bash
for f in ~/Code/*/scripts/build-icons.ts; do cmp -s "$f" ~/Code/beast-ui/scripts/build-icons.ts || echo "differs: $f"; done
```

To update an app, copy the file over, run `bun run icons:build`, and commit
`icons.ts` if it changed.

Later, the build could become a command of the published `@beastjs/cli`, so
apps would update by bumping a version instead of copying a file.

## Reference

### build-icons.ts

```
bun scripts/build-icons.ts --svg <folder> --out <file> [--check] [--unused <folder>]
```

| Flag | Meaning |
| --- | --- |
| `--svg <folder>` | The `.svg` files. Files in its `color/` subfolder keep their colors. |
| `--out <file>` | The `icons.ts` module to write. |
| `--check` | Fail instead of writing when `<file>` is out of date. |
| `--unused <folder>` | Also list icons whose name never appears in quotes under `<folder>`. It skips `node_modules`, `dist`, `build`, `out`, `coverage` and hidden folders. |

### migrate-icons.ts

```
bun ~/Code/beast-ui/scripts/migrate-icons.ts --svg <folder> <map.ts> [<map.ts> …] [--preview <file>]
```

| Argument | Meaning |
| --- | --- |
| `--svg <folder>` | Where to write the `.svg` files. Icons with their own colors go in `<folder>/color`. |
| `<map.ts>` | Modules that export `{ name: { symbol, viewBox } }` maps, such as `icons.ts` and `logos.ts`. Every such export is read. |
| `--preview <file>` | Where to write the comparison page. The default is `icons-preview.html` in the temp folder. |

It exits with an error when it skipped anything, after writing the rest.

### Icon props

| Prop | Beast | React |
| --- | --- | --- |
| `name` | Required. An `IconName`. | Same |
| `size` | Width and height in pixels. Default `20`. | Default `16` |
| `className` | Classes for the `<svg>`, as a string, array or object. | A string |
| `color` | Any CSS color. Default: the text color. | Same |
| `label` | Names an icon that means something on its own. Without it the icon is hidden from screen readers. | Same |
| Other `<svg>` props | Not accepted | Passed through |

### Messages

| Message | Fix |
| --- | --- |
| `"…" is not a valid icon name` | Rename the file: lowercase letters, digits and dashes. |
| `….svg needs a viewBox` | Add one. For `width="24" height="24"`, that is `viewBox="0 0 24 24"`. |
| `….svg is not well-formed SVG: …` | Browsers forgive broken markup, the build does not. Look at the line and column given for an unclosed tag, a tag closed twice, or an attribute without a value. |
| `….svg uses transform-origin=…` | Bake the transform into the path in your editor, or re-export the icon. |
| `….svg has nothing to draw` | The file has no shapes left after clean-up. Re-export it. |
| `….svg is in both the svg folder and its color/ subfolder` | Delete one of the two files. |
| `… does not exist. Pass the folder that holds your .svg files with --svg.` | Check the `--svg` path in `package.json`. |
| `… is out of date. Run bun run icons:build.` | Build, then commit `icons.ts`. |
| `has no symbol string in …` (migration) | Fix that entry in the old map, then migrate again. |
| `is in both … and …` (migration) | Two maps use the name. Rename one, and its call sites. |
| `… already exists.` (migration) | An earlier run wrote it. Delete the file to write it again. |
